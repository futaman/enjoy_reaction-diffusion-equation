# スマホ QA レポート（使いやすさと不具合の点検）

対象：`dist/index.html`（2026-10-26 に `node build.mjs` で作ったもの）。トップページ、はじめに、第1〜8章。
[QA レポート](qa-report.md)（PC 中心の通し確認）のあとに、スマホでの使いやすさに絞って点検しました。

## 点検した環境

- **ブラウザ：** Playwright の Chromium（153）。
  - **WebKit は使えませんでした。** この環境には WebKit の実行ファイルが入っていないので（`webkit.launch()` が失敗）、iPhone の Safari のまねはできていません。Firefox も同じです。
- **スマホのまね：** `isMobile: true`、`hasTouch: true`、`deviceScaleFactor: 3` で、次の3つの画面。
  - 360×740（小さめの Android）、390×844（iPhone 12〜15 くらい）、740×360（横向き）
  - 見た目は「📓 ノート」と「🐣 かわいい」の両方。360px では暗い表示（`rd-drill:theme` = `"dark"`）も両方の見た目で確認。
- **タッチ：** タップは `page.touchscreen.tap`。スワイプ、なぞり描き、つまみの操作は CDP の `Input.dispatchTouchEvent` で本物のタッチ（touchStart → touchMove → touchEnd）を送りました。`touch-action` の効き方もこれで確かめています。
- **遅いスマホのまね：** CDP の `Emulation.setCPUThrottlingRate` で CPU を 4 倍・6 倍遅くしました。
- **localStorage が使えない環境：** `addInitScript` で `localStorage` を読むと例外が出るようにしました。

**確かめられなかったこと**

- 本物の iPhone（iOS Safari）と Android の実機。とくに次の3つは実機でしか確かめられません。
  - iOS が入力欄をタップしたときに画面を拡大するか（CSS で 16px 以上にしたので、仕様上は拡大されないはず）
  - 数字のキーボード（`inputmode="decimal"`）の見た目。属性が付いていることは確認しました。
  - iOS のつまみ（range）は、つまみを直接つかまないと動かないこと。
- 画面の下のツールバーが出たり消えたりする iOS Safari での、`100svh` の効き方。
- 本物の遅い端末での体感速度（CPU を遅くしたまねで測っただけです）。

点検のスクリプトは `tmp/mobile/` にあります（`audit.cjs`：配置・押せる大きさ・文字の大きさ、`touch.cjs`：スワイプとブラシ、`func.cjs`：再生バーと全部の問題、`scenario.cjs`：再現チャレンジ・保存・切り替え・ループの取り残し・localStorage なし・電卓・つまみ、`perf.cjs`：長いタスクとフレームレート、`land.cjs`：横向き）。どれも `NODE_PATH=/opt/node-tools/node_modules node tmp/mobile/<名前>.cjs` で動きます。

## 問題なしと確かめたこと

- **スクロール：** どの章でも、草原・グラフ・棒グラフ・第7章の F-k マップ・第1章のグラフ・第3章の粒のキャンバスの上から縦にスワイプすると、ページがスクロールする（全 54 か所、ノートとかわいいの両方。CPU 6 倍遅いときも同じ）。指を止めるのは第8章のブラシの草原だけで、そこを指でなぞるとスクロールせずにウサギを描ける。
- **横はみ出し：** 360・390・740（横向き）、ノート・かわいい、明るい・暗いの 80 画面すべてで 0px。overflow で切れている文字も 0。
- **キャンバスの文字：** グラフ・F-k マップは表示幅 × 画素密度で描いていて、目盛りや軸の名前は 12〜13 CSS px（360px でも読める）。
- **上にくっつく部品：** 解説の横のデモ（`.step-demo`）と第8章の草原は、幅 960px 以上のときだけ上にくっつく。横向き（740px）ではくっつかず、本文を隠さない。ヘッダーは横向きでも高さ約 55px。
- **入力：** 数の欄はすべて `inputmode="decimal"`（第8章の名前の欄だけは文字なので付けていない）。Enter でも「答え合わせ」でも判定できる。全角や「−」も受け付ける。対応づけの選択欄はタップでえらべる。つまみは指でつまんで左右に動かせ、そのときページは縦に動かない。
- **再生バー：** 全章の再生バー（14 個）で、▶ 再生 / ⏸ 一時停止、1コマ進める、↺ はじめから、速さの切り替えがタップで動く。第7章の実験の再生バーは、予想するまで使えない（意図どおり）。
- **問題：** 全種類（選択・予想・数・マス・対応づけ・穴うめ）で、まちがえると赤の説明、正しいと緑の解説が出る。ヒントは3段階、最後に「答えを見る」。章のクリアでトースト「🎉 この章をクリアしました！」が1回だけ出て、「✓ この章はクリア済み」になる。トップのもくじにも ✓ が付く。
- **第7章の再現チャレンジ：** 数の欄に F と k を入れて Enter → 2000 コマで「水玉」「迷路」「分裂する点」に合格し、「クリアまで：問題0/5・再現3/3」と内訳が出る。コレクションに入る。
- **コレクション：** 第8章で名前を付けて保存 → トップのコレクションに出る → タップすると第8章が同じ F, k で開く。PNG 保存はダウンロードが始まり、エラーは出ない。
- **見た目・明るさの切り替え：** ページの途中で切り替えても、草原・グラフ・地図が描き直され、動いていたデモは動き続け、エラーは出ない。
- **戻る・進む、すばやい章の切り替え：** シミュレーションが動いている最中に戻る・進むをしても、正しい章が出る。9章を3周すばやく切り替えてからトップに戻ると、1 秒間の `requestAnimationFrame` は 0 回、`setInterval` は 0 個、Runner は 0 個（ループの取り残しはない）。
- **再読み込み：** 解いた問題と「クリアまで」の表示は残る。
- **localStorage が使えない：** エラーは出ず、問題を解く・見た目を切り替える・ラボで保存する・トップのコレクションに出る、まで動く（ページを閉じると消える）。
- **電卓：** 縦向きでは画面に収まり、タップで計算できる（1.5 × 2 = 3）。
- **コンソールのエラー・警告：** すべての点検で 0 件。
